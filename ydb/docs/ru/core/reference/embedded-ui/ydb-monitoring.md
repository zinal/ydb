# {{ ydb-short-name }} Monitoring

{{ ydb-short-name }} Monitoring — набор страниц встроенного UI, отображающих состояние кластера, баз данных, узлов и системы хранения. На страницах показаны перечни компонентов и их текущие параметры. Для многих компонентов перед названием выводится [цветовой индикатор](#colored_indicator) состояния.

Базовый адрес интерфейса:

```text
http://<эндпоинт>:8765/monitoring
```

Основные разделы:

* [Страница кластера](#main_page) — `/monitoring/cluster`
* [Страница базы данных](#database_page) — `/monitoring/database`
* [Страница узла](#node_page) — `/monitoring/node/<node-id>`

Устаревшие адреса `/monitoring/tenant` и `/monitoring/cluster/tenants` перенаправляют на `/monitoring/database` и `/monitoring/cluster/databases` соответственно.

## Страница кластера {#main_page}

Страница доступна по адресу:

```text
http://<эндпоинт>:8765/monitoring/cluster
```

или с указанием вкладки:

```text
http://<эндпоинт>:8765/monitoring/cluster/<вкладка>
```

В верхней части страницы отображается сводка по кластеру:

* **CPU** — суммарная загрузка пулов акторной системы на всех узлах;
* **Memory** — суммарное потребление оперативной памяти узлами кластера;
* **Storage** — использование дискового пространства (в том числе в разрезе типов носителей);
* **Network** — [использование сети](#network_usage) (процент и исходящий трафик Interconnect);
* **Nodes** — число узлов;
* при необходимости — дополнительные карточки, например прогресс выделения групп хранения или состояние bridge piles.

Ниже расположены вкладки:

| Вкладка | Path | Содержание |
| --- | --- | --- |
| **Databases** | `databases` | [Список баз данных](#tenant_list_page) |
| **Nodes** | `nodes` | [Список узлов](#node_list_page) |
| **Storage** | `storage` | Группы хранения и узлы хранения |
| **Network** | `network` | Состояние сетевых соединений между узлами |
| **Versions** | `versions` | Версии {{ ydb-short-name }} на узлах |
| **Tablets** | `tablets` | Таблетки кластера |
| **Events** | `events` | События |
| **Configs** | `configs` | Конфигурация |

Также доступен отчёт Healthcheck по состоянию кластера.

### Список баз данных {#tenant_list_page}

{{ ydb-short-name }} — мультиарендная СУБД: запросы к разным базам данных обрабатываются изолированно. В интерфейсе база данных соответствует тенанту.

В списке для каждой базы данных обычно отображаются:

* **Database** — путь базы данных;
* **Type** — тип (`Domain`, `Dedicated`, `Serverless` и др.);
* **State** — состояние;
* **CPU** — загрузка CPU узлами базы данных;
* **Memory** — потребление ОЗУ;
* **Storage** — оценка объёма хранимых данных;
* **Network** — исходящий трафик Interconnect (интенсивность);
* **Nodes** / **Groups** — число узлов и групп хранения;
* **Pools** — потребление CPU в разбивке по пулам акторной системы.

Тенант типа `Domain` обслуживает системные компоненты, необходимые для работы всех баз данных: в него входят узлы хранения и системные таблетки. Тенант типа `Dedicated` обслуживает пользовательскую базу данных.

При выборе базы данных открывается [страница базы данных](#database_page).

### Список узлов {#node_list_page}

Список содержит узлы кластера. Для каждого узла обычно отображаются:

* **Node ID** — идентификатор узла;
* **Host** — хост, на котором работает узел;
* **Uptime** — время работы узла;
* **Version** — версия {{ ydb-short-name }};
* загрузка CPU и потребление памяти;
* сведения о дисках (PDisk) и роли узла.

При выборе хоста или идентификатора узла открывается [страница узла](#node_page).

На вкладке **Storage** кластера можно просматривать группы хранения и узлы хранения, фильтровать проблемные группы, группировать данные и включать expert mode для расширенного представления.

## Страница базы данных {#database_page} {#tenant_page}

Страница доступна по адресу:

```text
http://<эндпоинт>:8765/monitoring/database?database=<путь-базы>
```

Пример открытия метрики сети на обзоре базы данных:

```text
http://<эндпоинт>:8765/monitoring/database?database=<путь-базы>&diagnosticsTab=database&metricsTab=network
```

В левой панели навигации доступны разделы:

* **Database** — обзор базы данных и основные диагностические вкладки;
* **Diagnostics** — подробная диагностика (узлы, таблетки, top shards, describe, access и др.);
* **SQL Editor** — выполнение YQL-запросов, история и сохранённые запросы.

Параметры URL:

* `database` — путь базы данных (устаревший параметр `name` также поддерживается);
* `databasePage` — раздел: `database`, `diagnostics` или `query`;
* `diagnosticsTab` — активная вкладка внутри раздела;
* `metricsTab` — активная метрика на Overview: `cpu`, `storage`, `memory` или `network`.

### Overview и метрики ресурсов {#database_overview}

На вкладке **Overview** (`diagnosticsTab=database`) отображается сводка по ресурсам базы данных. Переключение метрик выполняется параметром `metricsTab` или соответствующими вкладками в интерфейсе.

#### CPU {#database_cpu}

* Показывает суммарную загрузку пулов акторной системы базы данных, кроме пула **IO**.
* Ниже доступны детализация по пулам (**System**, **User**, **Batch**, **IO**, **IC**), а также списки наиболее загруженных узлов, шардов и запросов.

#### Storage {#database_storage}

* Показывает, сколько данных хранится в базе, включая пользовательские данные и индексы.
* Может включать сведения о пользовательских данных, физическом использовании дисков, квотах и overhead.
* Ниже доступны списки крупнейших таблиц и групп хранения с наибольшим использованием.

#### Memory {#database_memory}

* Показывает суммарное потребление памяти процессами базы данных.
* Ниже доступны детали по памяти и список узлов с наибольшим потреблением.

#### Network {#database_network} {#network_usage} {#tenant_network}

Карточка **Network usage** показывает две связанные, но разные величины:

1. **Интенсивность трафика** (например, `X MB/s`) — суммарный исходящий трафик Interconnect базы данных.
2. **Процент** — средняя утилизация исходящих очередей Interconnect по узлам базы данных.

Как считаются значения:

* **Трафик.** На каждом узле учитываются байты, записанные в сокеты peer-сессий Interconnect (`BytesWritten`). По дельтам этих счётчиков вычисляется исходящая скорость (`WriteThroughput`) для соединений с другими узлами. На уровне узла скорости по peer-сессиям суммируются в `NetworkWriteThroughput`. Для базы данных значения узлов **суммируются**. В карточке отображается именно этот исходящий bandwidth; входящий трафик и клиентский gRPC в эту величину не входят.

* **Процент.** На каждом узле `NetworkUtilization` — доля времени, в течение которого хотя бы одна сессия Interconnect имела данные в исходящей очереди (очередь отправки была непустой). Это отношение времени «есть что отправлять» к общему времени наблюдения, а не отношение трафика к пропускной способности сетевого интерфейса или канала. Для базы данных берётся **среднее** значение по узлам, которые отдают метрику. В интерфейсе доля `0…1` отображается как проценты (`0…100%`).

Таким образом, высокий процент означает, что исходящие очереди Interconnect часто непусты (сеть или приёмная сторона не успевают за отправкой), а не то, что утилизирован определённый процент ёмкости NIC.

Отображение процента можно отключить в настройках UI опцией **Show network utilization**.

На вкладке сети также доступны графики отправленного/принятого трафика и списки узлов с наибольшим ping и clock skew. Подробная таблица соединений между узлами находится на вкладке **Network** базы данных или кластера.

### Другие вкладки базы данных {#tenant_compute_page} {#tenant_storage_page}

В зависимости от выбранного раздела (**Database** или **Diagnostics**) доступны вкладки, в том числе:

* **Queries** / **Top shards** — наиболее ресурсоёмкие запросы и шарды;
* **Nodes** — узлы, обслуживающие базу данных (ранее вкладка Compute);
* **Tablets** — таблетки базы данных;
* **Storage** — группы хранения и узлы хранения базы данных; доступны фильтры вроде `Groups` / `Nodes`, `Degraded`, `Out of Space`;
* **Network** — таблица сетевых соединений;
* **Info**, **Describe**, **Access**, **Configs**, **Operations**, **Backups**, **Monitoring** — информационные и операционные вкладки.

Дерево схемы базы данных позволяет выбирать объекты (таблицы, топики и др.) и просматривать их свойства на объектных вкладках: **Info**, **Schema**, **Preview**, **Graph**, **ACL** и других — в зависимости от типа объекта.

### SQL Editor {#tenant_scheme}

Выполнение произвольных YQL-запросов, просмотр истории и сохранённых запросов доступны в разделе **SQL Editor** (`databasePage=query`).

## Страница узла {#node_page}

Страница доступна по адресу:

```text
http://<эндпоинт>:8765/monitoring/node/<node-id>
```

или с указанием вкладки:

```text
http://<эндпоинт>:8765/monitoring/node/<node-id>/<вкладка>
```

В заголовке и блоке общей информации обычно отображаются:

* идентификатор и хост узла;
* зона доступности (**DC**) и стойка (**Rack**);
* база данных, к которой относится узел;
* uptime и версия {{ ydb-short-name }};
* endpoints и роли узла;
* **Pools** — потребление CPU в разбивке по пулам акторной системы;
* **Load average** — средняя загрузка хоста за 1, 5 и 15 минут.

Назначение пулов:

* **System** — задачи критически важных системных компонентов;
* **User** — пользовательские задачи, исполнение запросов таблетками;
* **Batch** — длительные фоновые задачи;
* **IO** — блокирующие операции ввода-вывода;
* **IC** — обработка сетевого взаимодействия (Interconnect).

Высокая загрузка пулов может приводить к деградации производительности и росту времени отклика.

Вкладки страницы узла:

| Вкладка | Содержание |
| --- | --- |
| **Storage** | Группы хранения / VDisk / PDisk, связанные с узлом |
| **Structure** | Структура компонентов узла |
| **Tablets** | Таблетки, запущенные на узле |
| **Threads** | Потоки пулов, использование CPU, page faults |
| **Network** | Сетевые соединения узла |
| **Configs** | Конфигурация узла |

### Группы хранения на узле {#node_storage_page}

Для узлов хранения список содержит группы, данные которых размещены на дисках этого узла. Для динамических узлов показываются группы хранения базы данных, к которой относится узел.

Группы можно раскрыть до списка VDisk. Для VDisk обычно отображаются идентификаторы VDisk и PDisk, узел размещения, доступное место и путь к блочному устройству.

### Таблетки на узле {#node_tablets_page}

Многие компоненты {{ ydb-short-name }} реализованы как таблетки. Система может перемещать таблетки между узлами.

В списке таблеток каждая таблетка представлена [цветовым индикатором](#colored_indicator). При наведении доступна краткая информация:

* **Tablet** — идентификатор таблетки;
* **NodeID** — узел, на котором работает таблетка;
* **State** — состояние;
* **Type** — тип;
* **Uptime** — время работы с момента текущего запуска;
* **Generation** — поколение (номер текущей попытки запуска).

## Мониторинг статической группы {#static-group}

Чтобы проверить статус статической группы, откройте вкладку **Storage** на странице кластера или базы данных. По умолчанию могут отображаться группы с проблемами.

В поисковой строке введите `static`. Если результат пуст, у статической группы проблем не обнаружено. Если группа **static** присутствует в выдаче, проверьте статус её VDisk:

* **зелёный** — проблем нет;
* **синий** — выполняется репликация;
* **красный** — есть проблема.

Наведите курсор на индикатор, чтобы получить текстовое описание состояния.

## Индикаторы состояний {#colored_indicator}

Слева от названия компонента может отображаться цветовой индикатор его состояния.

| Цвет | Значение |
| --- | --- |
| **Зелёный** | Проблем нет, компонент работает в штатном режиме |
| **Синий** | Идёт репликация данных, других проблем нет |
| **Жёлтый** | Возможны проблемы, компонент продолжает работать |
| **Красный** | Критические проблемы: компонент не работает или работает с ограничениями |

Если компонент включает другие компоненты и собственных проблем не имеет, его состояние определяется агрегированием состояний частей.
